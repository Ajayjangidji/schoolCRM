Executive Summary

SchoolAI CRM is a comprehensive, AI-powered school management platform designed specifically for Indian K-12 schools. The platform connects three key stakeholders — Parents, Teachers, and School Administration — through dedicated modules, each tailored to their specific needs and workflows.

Phase 1 (MVP) delivers 45 core features across 3 modules, with integrated AI assistance at every level. The AI layer differentiates SchoolAI from traditional ERPs by providing intelligent insights, automated content generation, and natural-language query support.

Core Differentiator: Unlike traditional school ERPs that are data-entry systems, SchoolAI uses AI to transform raw school data into actionable insights, automated communications, and intelligent assistance for every user role.

Product Vision

Mission: Make school management effortless through AI-powered automation, real-time communication, and data-driven insights — so teachers can focus on teaching, parents stay connected, and admins run operations smoothly.

Key Goals

  • Real-time transparency — Parents see attendance, homework, and fees as they happen, not days later
  • Teacher productivity — One-click attendance, AI-generated homework and remarks, automated report cards
  • Admin intelligence — AI surfaces fee defaulters, attendance anomalies, performance trends without manual analysis
  • Multi-channel communication — App push, SMS, WhatsApp, and email from one center

User Personas

Parent / Guardian
Wants instant updates on their child's school life. Checks the app 2-3 times daily — morning (bus tracking), afternoon (homework), evening (daily summary). Pays fees online. Needs Hindi + English support. Primary device: smartphone (Android 80%, iOS 20%).
Teacher
Manages 30-50 students per class, 3-5 classes per day. Marks attendance in 2 minutes. Assigns homework from phone between classes. Wants AI to write report card remarks. Uses tablet or laptop in staffroom, phone in classroom.
Super Admin / Principal
Oversees entire school operations. Needs high-level dashboards with drill-down capability. Manages 500-3000 students, 30-150 staff. Monitors fee collection daily. Sends announcements to specific groups. Primarily uses desktop/laptop.

01 Dashboard Must Have ▶

Description

The home screen after login. A single-glance overview of everything important about the child's school day. Designed for a parent who opens the app for 30 seconds and wants to know: "Is everything okay today?"

User Stories

"As a parent, I want to see my child's attendance, pending homework, and any school announcements on one screen so I don't have to navigate multiple pages."
"As a parent with 2 children in the same school, I want to switch between their profiles easily."

UI Components & Data Displayed

  • Child Profile Switcher (top bar): Child's photo, name, class & section, roll number. Tap to switch if multiple children enrolled.
  • Today's Attendance Card:
    • • Status badge: Present / Absent / Late
    • • Time of check-in (if recorded via biometric/RFID)
    • • Monthly attendance percentage as a small ring chart (e.g., 92%)
  • Homework Summary Card:
    • • Count of pending homework items (e.g., "3 pending")
    • • Next due date with urgency color (red if due today/tomorrow)
    • • Subject-wise mini list (Math, Science, English...) with status dots
  • Fee Status Card:
    • • Current dues amount in INR (e.g., "₹15,000 due")
    • • Due date with days remaining
    • • Quick "Pay Now" button linking to payment gateway
    • • Green checkmark if all fees are cleared
  • Announcements Carousel: Latest 3-5 announcements as horizontal cards. Priority announcements pinned. Each shows title, date, and category tag (Holiday/Exam/Event/General).
  • Upcoming Events Strip: Next 3 events in chronological order — event name, date, and type icon.
  • Quick Action Buttons: Leave Request, Chat with Teacher, View Timetable, Pay Fees — 4 shortcut buttons in a 2x2 grid.
  • AI Assistant Floating Button: Bottom-right corner, opens the conversational AI chat interface.

Business Rules

  • Dashboard data refreshes every 60 seconds when app is in foreground.
  • Attendance card shows "Awaiting" state until teacher marks attendance for the day.
  • Fee card only appears if there are current or upcoming dues within 30 days.
  • Announcements older than 30 days auto-archive from carousel.
  • Child switcher only appears if parent has >1 child enrolled.

Notifications Triggered

None directly Dashboard is a consumer of data, not a producer. Notifications come from individual features.
02 Attendance Must Have ▶

Description

Detailed attendance tracking and history for the child. Goes beyond "present/absent" to show patterns, trends, and subject-wise attendance where applicable. Parents receive instant notifications when attendance is marked.

User Stories

"As a parent, I want to get notified immediately when my child is marked absent so I can verify if they actually reached school."
"As a parent, I want to see monthly/yearly attendance patterns to identify if my child is missing school too often."

UI Components & Data Displayed

  • Today's Status Banner: Large status display — Present (green) / Absent (red) / Late (amber) / Half-Day (blue). Shows marked time and marked-by teacher name.
  • Monthly Calendar Heatmap:
    • • Calendar grid with color-coded days: Green (present), Red (absent), Amber (late), Grey (holiday/weekend), Blue (half-day)
    • • Tap any day to see detailed info (check-in time, marked by, leave type if applicable)
  • Statistics Panel:
    • • Total working days this month / year
    • • Days present / absent / late
    • • Attendance percentage (month & year-to-date)
    • • Comparison with class average (optional)
  • Trend Chart: Line graph showing monthly attendance percentage over the academic year.
  • Subject-wise Attendance (if tracked): Table showing attendance per subject for higher classes where period-wise attendance is maintained.
  • Leave History Link: Quick link to approved/pending leave requests that correlate with absent days.

Business Rules

  • Attendance percentage below 75% triggers a warning indicator on the dashboard and monthly reports.
  • 3 consecutive absent days without approved leave triggers a push notification + SMS to parent and an alert to class teacher.
  • Attendance can only be marked by assigned teacher or admin — parents have read-only access.
  • Late arrival threshold is configurable per school (default: 15 min after school start).
  • Attendance data is immutable after 48 hours unless modified by admin with audit trail.

Notifications Triggered

Absent Marked: Instant push + optional SMS — "Your child [Name] has been marked absent today in Class [X]."
Late Marked: Push notification — "[Name] arrived late at [time]."
Low Attendance: Weekly digest if attendance drops below 80% — "[Name]'s attendance is [X]% this month."
3-Day Absence: Alert notification + SMS after 3 consecutive absences.
03 Homework Must Have ▶

Description

View all assigned homework, track completion status, submit work (photo/file upload), and receive due-date reminders. Replaces the physical homework diary with a digital, trackable, and searchable system.

User Stories

"As a parent, I want to see all pending homework in one place so I can help my child complete it on time."
"As a student, I want to submit my homework by taking a photo of my notebook so I don't have to type everything."

UI Components & Data Displayed

  • Homework List View (default):
    • • Tabs: "Pending" | "Submitted" | "Evaluated" | "Overdue"
    • • Each item shows: Subject icon + name, homework title, assigned date, due date, teacher name
    • • Status badges: Pending (amber), Submitted (blue), Evaluated (green with grade), Overdue (red)
    • • Sort by: Due date (default) | Subject | Date assigned
  • Homework Detail View (tap to expand):
    • • Full description of the homework with formatting (bold, lists, etc.)
    • • Attachments from teacher (PDF worksheets, images, reference links)
    • • Submission area: Upload photo (camera/gallery), upload file (PDF/DOC), text input for typed answers
    • • Max file size indicator and supported formats
    • • Teacher's feedback/grade (after evaluation) with remarks
  • Subject Filter: Horizontal chips to filter by subject (All | Math | Science | English | Hindi | ...)
  • Calendar View (toggle): Switch between list and calendar views to see homework mapped to dates.

Business Rules

  • Homework assigned after school hours appears in the app by 6 PM same day.
  • Submission allowed until 11:59 PM on the due date (configurable per school).
  • Late submissions are accepted but flagged as "Late" with a visual indicator.
  • Maximum 5 file uploads per homework, each up to 10 MB.
  • Supported formats: JPG, PNG, PDF, DOC, DOCX.
  • Once submitted, student can re-submit (overwrite) until the teacher starts evaluation.
  • Teacher must evaluate homework within 7 days (configurable), system sends reminders after 3 days.

Notifications Triggered

New Homework: Push notification when teacher assigns — "New [Subject] homework: [Title]. Due: [Date]."
Due Reminder: Push at 6 PM one day before due date — "[Subject] homework due tomorrow."
Overdue Alert: Push at 8 AM day after due — "[Subject] homework is overdue."
Evaluated: Push when teacher grades — "Your [Subject] homework has been evaluated. Grade: [X]."
04 Academic Progress Must Have ▶

Description

Comprehensive academic performance tracking — marks, grades, report cards, subject-wise analysis, and term comparisons. Parents see not just the numbers but the trend and context.

User Stories

"As a parent, I want to compare my child's performance across terms to see if they are improving."
"As a parent, I want to download the report card as PDF to save or share."

UI Components & Data Displayed

  • Performance Overview Card:
    • • Overall percentage / CGPA / Grade (based on school's grading system)
    • • Class rank (if school enables this)
    • • Term selector dropdown: "Term 1" | "Term 2" | "Annual" | "Unit Test 1" etc.
  • Subject-wise Marks Table:
    • • Columns: Subject, Marks Obtained, Total Marks, Percentage, Grade
    • • Color-coded rows: Green (>80%), Amber (50-80%), Red (<50%)
    • • Expandable rows to show marks breakdown (Theory, Practical, Internal Assessment)
  • Subject Radar Chart: Spider/radar chart showing performance across all subjects visually.
  • Term Comparison Bar Chart: Side-by-side bars comparing Term 1 vs Term 2 per subject.
  • Report Card View:
    • • Official digital report card with school branding
    • • Includes: Student details, marks, attendance summary, teacher remarks, principal remarks

    • • Share button (WhatsApp, email)

Business Rules

  • Class rank display is configurable per school — some schools may choose to hide it.
  • Report card PDF generation uses the school's official template with digital watermark.
  • Grading system supports: Percentage, CGPA (10-point), Letter Grades (A+ to F), or custom as defined by the school.
  • Marks cannot be edited by teachers after admin locks the result; only admin can unlock.

Notifications Triggered

Results Published: "Term 1 results are now available. View your child's report card."
Low Performance Alert: If any subject drops below 40% — "[Name] scored below passing in [Subject]. Please review."
05 Fee Management Must Have ▶

Description

Complete fee lifecycle from the parent's perspective: view fee structure, check due amounts, pay online through integrated payment gateway, download receipts, and view payment history.

User Stories

"As a parent, I want to pay school fees from the app via UPI/card/netbanking without visiting school."
"As a parent, I want to download fee receipts for tax deduction and record-keeping."

UI Components & Data Displayed

  • Fee Summary Card:
    • • Total annual fee, amount paid, balance remaining
    • • Visual progress bar showing % paid
    • • Next due amount and due date (prominently displayed)
    • • Overdue amount in red with days overdue
  • Fee Structure Breakdown:
    • • Table: Fee Head (Tuition, Transport, Lab, Library, etc.), Amount, Frequency (Monthly/Quarterly/Annual), Status
    • • Applicable discounts (sibling discount, scholarship, early-bird) shown as line items
    • • Late fee calculation displayed separately
  • Pay Now Flow:
    • • Select installment(s) to pay (checkboxes)
    • • Apply coupon/discount code (if applicable)
    • • Total amount with GST breakdown
    • • Payment methods: UPI (GPay, PhonePe, Paytm), Credit/Debit Card, Net Banking, EMI options
    • • Payment gateway integration (Razorpay / CCAvenue / PayU)
    • • Payment confirmation screen with transaction ID
  • Payment History:
    • • List of all payments: Date, Amount, Payment Mode, Transaction ID, Status (Success/Failed/Pending)
    • • Download receipt for each payment (PDF)
    • • Filter by academic year

Business Rules

  • Late fee starts accruing after the due date based on school's late fee policy (flat amount or daily/monthly percentage).
  • Partial payments are allowed — system tracks remaining balance per installment.
  • Payment receipt is auto-generated and emailed within 5 minutes of successful payment.
  • Failed payment attempts are logged and visible in payment history for troubleshooting.
  • Refunds follow a separate workflow — parent requests, admin approves, system processes.
  • Fee concessions/scholarships can only be applied by admin; parent sees the adjusted amount.
  • Duplicate payment detection: system prevents double-charge within a 5-minute window for the same installment.

Notifications Triggered

Fee Due Reminder: 7 days before due date — "Fee of ₹[Amount] for [Term] is due on [Date]."
Fee Overdue: On due date + 1 day — "Fee payment of ₹[Amount] is overdue. Late fee may apply."
Payment Success: Instant — "Payment of ₹[Amount] received. Receipt: [ID]. Thank you!"
Payment Failed: Instant — "Payment of ₹[Amount] failed. Please try again."

07 Leave Request Must Have ▶

Description

Digital leave application system. Parents apply for their child's leave from the app, teachers/admins approve or reject, and the absence is auto-linked to attendance records.

User Stories

"As a parent, I want to apply for my child's leave from the app instead of writing a letter."

UI Components & Data Displayed

  • Apply Leave Form: Leave type dropdown (Sick, Personal, Family Emergency, Religious, Other). Date picker: From date & To date. Reason text area (required, min 10 characters). Attach supporting document (medical certificate, etc.) — optional. Submit button.
  • Leave History: List of all leave requests with status: Pending (amber), Approved (green), Rejected (red), Cancelled (grey). Each shows: Date range, type, reason summary, approved/rejected by, remarks from teacher.

Approved/Rejected: Push to parent — "Leave request for [Dates] has been [approved/rejected]. Remarks: [...]"

Description

Real-time GPS tracking of the school bus. Parents can see where the bus is, get ETA for pickup/drop, and receive alerts when the child boards or alights.

Secure, in-app messaging between parents and teachers. Replaces personal WhatsApp communication with a professional, auditable channel that respects teacher boundaries.

UI Components & Data Displayed

13 AI Assistant Must Have ▶

Description

Conversational AI chatbot that answers parent queries in natural language. Instead of navigating through menus, parents simply ask questions and get instant answers pulled from their child's actual data.

User Stories

"As a parent, I want to ask 'Is homework pending?' and get a direct answer instead of navigating to the homework section."
"As a parent, I want to ask in Hindi 'Meri beti ka result kab aayega?' and get a response."

How It Works

The AI does not use pre-trained general knowledge to answer school queries. It is a Retrieval-Augmented Generation (RAG) system that pulls data from the school's actual database and formulates natural-language responses.

Supported Query Categories

  • Attendance: "Was my child present today?" / "What is the attendance this month?" / "How many days absent?"
  • Homework: "Any pending homework?" / "What is the Math homework?" / "When is Science homework due?"
  • Fees: "How much fee is pending?" / "When is the next fee due?" / "Show my payment history"
  • Exams: "When is the next exam?" / "What subjects are in the exam?" / "Show Term 1 results"
  • Timetable: "What classes are today?" / "When is the Science period?" / "Any class change tomorrow?"
  • Notices: "Any new notices?" / "Is there a holiday this week?" / "What events are coming up?"
  • Transport: "Where is the bus?" / "When will the bus reach?" / "Who is the bus driver?"
  • General: "What are school timings?" / "What is the school phone number?" / "Who is the class teacher?"

Language Support

  • English and Hindi (Phase 1)
  • Hinglish (mixed Hindi-English) supported naturally
  • Auto-detects language from input and responds in the same language

Fallback Behavior

  • If AI cannot answer: "I don't have this information. Would you like to chat with the class teacher?"
  • If query is outside school scope: "I can only help with school-related questions."
  • If data is unavailable: "This information hasn't been updated yet. Please check back later."

Business Rules

  • AI only accesses data the parent is authorized to see (their own child's data).
  • No cross-student data leakage: Parent A cannot ask about Parent B's child.
  • Conversation history retained for 30 days for context.
  • Rate limit: 50 queries per parent per day.
  • Response time target: <3 seconds for text responses.

A single consolidated notification sent every evening summarizing the child's entire day — so parents who don't check the app frequently get a one-stop overview.

UI Components & Data Displayed

    • • Attendance: Present/Absent/Late with check-in time

15 Emergency Alerts Must Have ▶

Description

High-priority, non-dismissible alerts for critical situations. Bypasses all notification preferences — parents always receive these.

UI Components & Data Displayed

  • Full-screen Alert Overlay: When app is open, shows a red full-screen alert that must be manually dismissed.
  • Alert Content: Emergency type (Safety, Medical, Weather, Operational), details text, action instructions, school contact number, timestamp.

Emergency Types

  • Safety: Lockdown, fire drill, security incident
  • Medical: Child injury/illness, epidemic advisory
  • Weather: School closure due to weather, early dismissal
  • Operational: Bus breakdown, water/power outage, schedule change

Business Rules

  • Only Super Admin and Principal can trigger emergency alerts.
  • Sent via ALL channels simultaneously: Push + SMS + WhatsApp + Email.
  • Cannot be muted or silenced by parent's notification preferences.
  • Delivery confirmation required — system retries via SMS if push delivery fails within 2 minutes.
  • Emergency alert history maintained for compliance and audit.

Module 2 — Teacher

Designed for teachers to manage their daily tasks efficiently. Every feature is optimized for quick action — teachers are busy, so the app must save time, not add work. The AI assistant is a force multiplier here, generating content that teachers typically spend hours writing manually.

01 Teacher Dashboard Must Have ▶

Description

Teacher's home screen. Shows today's teaching schedule, pending tasks, and important updates. Designed as a morning briefing — teacher opens the app and knows exactly what their day looks like.

UI Components & Data Displayed

  • Today's Classes Timeline: Period-wise schedule: period number, time, class & section, subject. Current/next period highlighted. Shows room number if applicable.

Business Rules

  • Dashboard shows only classes assigned to this teacher.
  • Pending tasks are sorted by urgency (overdue first, then due today).
  • Dashboard reflects substitution assignments in real-time.
02 Attendance Management Must Have ▶

Description

Mark attendance for an entire class in under 2 minutes. Defaults to "present" for all students — teacher only marks exceptions (absent/late). Instant notification goes to parents of absent students.

UI Components & Data Displayed

Notifications Triggered

To Parents: Instant push when child marked absent/late.
To Teacher (reminder): "Attendance not marked for Class [X] Period [Y]."

AI Assistant — Deep Dive

The AI layer is what differentiates SchoolAI from traditional school ERPs. Here's how it works under the hood.

Architecture: How the AI Works

1
User Query
Parent/Teacher types a question in natural language (Hindi/English/Hinglish)
2
Intent Detection
NLP model identifies the intent (attendance? fees? homework?) and entities (which student, date, subject)
3
Data Retrieval
System queries the school database for relevant data based on the detected intent. Only data the user is authorized to see.
4
Response Generation
LLM formats the retrieved data into a natural, conversational response in the user's language.

AI Technology Stack

ComponentPurposeOptions
LLM (Language Model)Natural language understanding & generationClaude API / OpenAI GPT-4 / Google Gemini
Intent ClassifierCategorize user query into predefined intentsFine-tuned classifier or LLM function-calling
RAG PipelineRetrieve school data relevant to the queryCustom query builder mapping intents to DB queries
Language DetectionDetect Hindi/English/HinglishBuilt-in LLM capability
Content GenerationHomework, quizzes, remarks, lesson plansLLM with school curriculum context

How the AI Learns & Improves

  • It does NOT learn from individual student data — it is not trained on school data. It uses school data at query-time (RAG), not training-time.
  • Content quality improves via feedback loop: When a teacher edits AI-generated homework before publishing, that edit pattern is logged. Over time, the AI adjusts its generation style to match the teacher's preferences.
  • Failed queries are logged: When the AI cannot answer a question, it's logged for review. These gaps are addressed by adding new intent handlers or data mappings.
  • School-specific context: Each school's AI is contextualized with their academic calendar, subjects, grading system, and policies — so it gives school-specific answers, not generic ones.

Data Privacy & Safety

  • Student data is never sent to external AI services for training.
  • API calls to LLM providers use data-processing agreements (DPA) — data is not retained by the provider.
  • All AI interactions are logged for audit: who asked what, what data was accessed, what was the response.
  • Parent A cannot query data about Parent B's child — strict data isolation per family.

Cross-Module Data Flow

Data flows bidirectionally between modules. Here are the key connections:

  • Teacher marks attendance → Parent sees it instantly on dashboard + attendance screen + daily summary. Admin sees it in school dashboard + reports.
  • Teacher assigns homework → Parent gets notified, sees it in homework section + dashboard + daily summary. AI can answer queries about it.
  • Admin defines fee structure → Parent sees dues in fee management + dashboard. Admin tracks collection in reports. AI answers fee queries.
  • Teacher enters marks → Admin publishes results → Parent sees report card in academic progress + document vault. AI generates insights for admin.
  • Parent applies leave → Teacher approves → Attendance auto-marked as "On Leave" for those dates.
  • Admin creates timetable → Teacher sees their schedule → Parent sees child's timetable. Substitutions propagate in real-time.
